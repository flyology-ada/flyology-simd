The Wide AVX2 lookup is a static build selection. The build accepts it only with FLYOLOGY_SIMD_ARCH=x86_64 and FLYOLOGY_SIMD_AVX2=enabled. The static lookup performs no runtime feature check. Deploy that build only where CPUID reports the AVX, AVX2, and OSXSAVE bits, and XCR0 enables XMM and YMM register state. The whole-buffer AVX2 algorithms use a separate runtime feature gate.

On AArch64, 64-bit integer multiplication and the 64-bit integer Reduce_Add_Wrap, Reduce_Min, and Reduce_Max operations use scalar composition. On SSE2, 32- and 64-bit saturating arithmetic and all integer reduction operations use scalar composition. The SSE2 backend also uses scalar composition for floating Min_Number, Max_Number, Reduce_Add, Reduce_Min_Number, and Reduce_Max_Number.

The x86-64 backend uses scalar composition for Widen_Low, Widen_High, Narrow_Truncate, and Narrow_Saturate. Bit_Cast uses the same Ada implementation in both target backends. This fact does not make the private vector representation portable. The code-generation script lists the instruction classes that have positive checks.

Wide bit casts apply the selected 128-bit bit cast to each private part. Wide two-source lane maps use fixed-width Ada composition. That composition calls lane-access operations from the selected 128-bit backend. Wide conversions compose the corresponding selected 128-bit operations. These mechanisms have no dedicated 256-bit instruction claim. The optional x86-64 AVX2 Wide lookup is the only current exception.

Compiler scope

The executed compiler evidence uses GNAT FSF 16.1.0. GCC-based GNAT is the initial required compiler family.

GNAT LLVM remains a compatibility target. It is not an implemented or tested backend in this release.

Continuous checks

The workflow runs checked and release builds. Semantic checks include deterministic differential tests, independent lane oracles, full-width pseudorandom integer data, and floating-point edge cases.

The conversion tests cover integer truncation and saturation boundaries. Same-width signed/unsigned cases cover negative signed inputs around zero and unsigned inputs around the signed maximum. They also use deterministic, full-width pseudorandom inputs for the supported 8-, 16-, 32-, and 64-bit lanes. The tests cover F32 widening for signed zeros, subnormal and normal boundaries, infinities, and NaNs. Binary64 narrowing cases cover positive and negative halfway values, maximum finite binary32 values, overflow, gradual underflow to binary32 subnormals, underflow to signed zero, infinities, and NaNs. Integer-to-floating cases use an independent bit-level rounding oracle with deterministic, full-width pseudorandom inputs. Floating-to-integer cases use a separate bit-level oracle and raw pseudorandom floating encodings.

Memory checks include every tail length, protected pages, and AddressSanitizer. Code-generation checks inspect primitive operations and representative buffer loops.

A contract-parity gate compares the 588 declarations in Backends.Scalar with the matching 588 declarations in Backends.Native. It fails when a primitive overload exists in only one backend contract.

Mask patterns and first/last true-lane results are exhaustive for each mask width. The 128-bit and Wide byte-table tests cover every unsigned byte index, a fixed mixed mapping, and deterministic pseudorandom tables and indexes. An independent lane oracle defines both results. AArch64 code-generation checks require one-register tbl for the 16-entry operation and two-register tbl for each half of the Wide operation.

The x86-64 Wide AVX2 lookup runs the same differential cases. Its code-generation gate requires one mechanism call from the public caller. The isolated implementation subprogram must contain vpshufb, vperm2i128, vpsubusb, and vzeroupper. Baseline objects must contain no AVX instruction.

An independent lane oracle checks fixed maps for all ten value types. For each type, the tests run 250 deterministic cases. The cases use pseudorandom one-source selectors and two-source selectors that vary the source and lane. The tests also check each default-initialized two-source map. Floating cases include repeated selectors and compare special IEEE encodings bit for bit. AArch64 code-generation probes require one-register and two-register tbl forms through public byte, 16-bit integer, binary32, and binary64 overloads.

Lane-slide tests cover zero, every in-range count, and oversized counts for all ten value types. They compare both native directions with independent lane results and deterministic pseudorandom vectors. Floating slide cases also preserve special IEEE encodings bit for bit.

Compression and expansion tests exhaust every mask pattern for all ten value types. They compare the scalar authority and native backend with independent lane oracles. Deterministic pseudorandom vectors exercise the integer families. Floating cases preserve NaNs, infinities, and signed zeros bit for bit. AArch64 code-generation checks require tbl in every compression and expansion overload.

wide_tests checks all ten Wide value types. It compares scalar and Native arithmetic, comparisons, selection, masks, reductions, lane movement, slides, ordinary memory, unaligned memory, and partial memory. It also checks a Native aligned-memory round trip. The tests cover every partial-memory count and use 128 deterministic pseudorandom inputs per value type.

A separate case sets every lane to 255 and checks the Wide exact byte sum of 8,160. Fixed-vector and deterministic pseudorandom cases compare scalar and Native results with an independent lane oracle. AArch64 and x86-64 caller-level code-generation checks require two calls to the target-selected 128-bit exact byte-sum operation.

Fixed two-source maps compare scalar and Native results for every value type. Bit-cast round trips cover every same-shape pair. Floating map and bit-cast cases preserve special encodings bit for bit.

For each of the 46 Wide conversion overloads, tests use fixed vectors and 32 deterministic pseudorandom inputs. They compare scalar and Native results with results from the 128-bit authority. Direct floating-point edge cases cover signed zeros, infinities, quiet and signaling NaNs, subnormals, halfway rounding, overflow, and explicit floating-to-integer outcomes in both private parts. Caller-level code-generation probes require two selected 128-bit calls for representative widening, narrowing, and integer-to-floating conversion operations. The project does not claim a 256-bit instruction sequence.

Other floating cases distinguish signaling-NaN reduction order, check the positive-zero addition start, and preserve special encodings through slides. The guarded-page suite places every byte tail from zero through 32 immediately before an inaccessible page. Wide code-generation probes require two selected 128-bit calls for byte addition, binary32 multiplication, and binary32-to-unsigned-32 bit casts. They do not claim a 256-bit instruction sequence.

Floating reduction cases include NaNs, infinities, and signed zero. The protected-page test runs all 128-bit byte-tail counts from 0 through 16 and all Wide byte-tail counts from 0 through 32. AVX2 jobs require executable AVX2 coverage and do not silently skip it.

The workflow does not use continue-on-error.

Current limits

  • The public API is experimental.
  • The verified compiler matrix contains one GNAT FSF version.
  • Only Wide U8x32 Table_Lookup has an AVX2-specific 256-bit primitive implementation and code-generation claim.
  • The Wide AVX2 lookup is selected at build time. On each deployment target, CPUID must report the AVX, AVX2, and OSXSAVE bits, and XCR0 must enable XMM and YMM register state.
  • The three AVX2 whole-buffer byte algorithms use a separate runtime feature gate.
