Read the final bytes without overreading

Chapter 3 follows the byte-count loop to its array boundary. It defines the valid extent of full, unaligned, aligned, and partial operations.

The comma-counting input has 26 bytes. The first iteration processes 16 bytes. The final iteration must read the remaining ten bytes and no others.

Partial operations use an exact count

Load_Partial reads Count elements. It sets all remaining lanes to zero. Store_Partial writes Count elements.

A count of zero reads no element and writes no element. A partial operation does not perform a full vector access and then mask the result.

Process the final partial count block

The tutorial loop calculates the valid count before each load. After each nonfinal load, it advances by that count.

The loop calls Backends.Native and processes U8x16 values. Its Splat operation constructs the comma vector:

package Native renames Flyology_SIMD.Backends.Native;

Start : Natural := Data'First;
Total : Natural := 0;
Wanted : constant U8x16 := Native.Splat (Comma);

while Start <= Data'Last loop
   declare
      Remaining : constant Natural := Data'Last - Start + 1;
      Count : constant Lane_Count_8x16 :=
        Lane_Count_8x16'Min (16, Remaining);
      Values : constant U8x16 :=
        Native.Load_Partial (Data, Start, Count);
      Matches : constant Mask_8x16 := Native.Equal (Values, Wanted);
   begin
      Total := Total + Native.Population_Count (Matches);
      exit when Count = Remaining;
      Start := Start + Count;
   end;
end loop;

The first load reads array indexes 1 through 16. The second load reads indexes 17 through 26. It fills lanes 10 through 15 with zero. The loop exits after the final load and does not calculate an index after Data'Last.

Count has type Lane_Count_8x16. Matches has type Mask_8x16.

Native.Load_Partial enforces the exact read extent. Native.Equal compares the lanes, and Native.Population_Count counts matches.

The comma byte is not zero, so those filled lanes compare false. If a general byte-count function accepts zero as the searched value, it must mask unused lanes or use a scalar tail.

The repository contains the complete tutorial in examples/count_byte.adb.

Test the page boundary

guard_page_tests allocates two pages and denies all access to the second page. For each count from 0 through 16, it puts the valid bytes directly before that protected page.

The test calls scalar and native partial loads and stores. An access beyond the valid count enters the protected page and terminates the test. The suite also runs exact-size array tests and AddressSanitizer builds.

Apply lane order to every memory form

Load (Data, Start) puts Data (Start) in lane 0. It puts Data (Start + 1) in lane 1.

This rule defines the logical result. It does not define a portable record layout, register layout, or calling convention.

Full operations require one complete vector

Load and Store require enough valid elements for one vector. For U8x16, they require 16 elements. They do not require a 16-byte-aligned address.

Load_Unaligned and Store_Unaligned have the same behavior. Their names make the lack of an alignment requirement explicit at the call site.

Block : constant U8x16 := Load_Unaligned (Data, Start);
Store_Unaligned (Output, Start, Block);

Aligned operations require a 16-byte-aligned address

Is_Aligned_16 checks the address of Data (Start). Load_Aligned and Store_Aligned have a precondition that requires this check to be true.

Enabled assertion checks detect a false precondition. Your program must still meet the precondition when assertion checks are disabled.
