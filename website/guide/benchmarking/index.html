Run the benchmark

The benchmark is a separate Alire crate. It uses flyology_bench and measures complete byte-count operations.

Build and run from the benchmark crate

cd benchmarks
alr build --release
FLYOLOGY_BENCH_OUTPUT=terminal alr run --skip-build simd_benchmark

Alire detects an AArch64 or x86-64 host. To measure only the scalar configuration, rebuild with this scenario:

alr build --release -- -XFLYOLOGY_SIMD_ARCH=scalar

Use FLYOLOGY_BENCH_OUTPUT=csv or json for machine-readable output. Generated results are not version-controlled.

Measure four complete implementations

Each input size compares:

  • a direct ordinary Ada loop;
  • the scalar SIMD algorithm;
  • the statically selected native algorithm;
  • the runtime-dispatched algorithm.

The input sizes are 7, 15, 16, 17, 4,096, and 1,048,576 bytes. These cases cover short input, the 16-byte boundary, cache-resident input, and larger streaming input.

Use repeated and balanced measurements

The program calls Flyology_Bench.Compare_Many. It uses 250 ms of warmup, equal-time calibration, 75 samples, balanced candidate order, and three seconds of measurement for each comparison.

The report keeps raw samples and calculates bootstrap confidence intervals. It reports candidate-order effects and lag-one correlation. It does not remove outliers automatically or subtract an estimated timer cost.

A checksum makes each result observable. The report includes the compiler, build switches, selected backend, and CPU features.

Optional host controls

Set FLYOLOGY_BENCH_QUIESCENCE=1 to wait for a quiet host. Set FLYOLOGY_SIMD_BENCH_CPU to request CPU pinning. The report states whether each control succeeded.

Recorded AArch64 observation

On 2026-08-10, an Apple Mac15,9 AArch64 host used GNAT FSF 16.1.0. Library objects used -O2 -ftree-vectorize. Benchmark code used -O3. The following values are medians from that run:

BytesOrdinary AdaScalarStatic NEONRuntime
167.07 ns14.20 ns5.86 ns7.25 ns
4,0961,349.29 ns3,130.04 ns661.40 ns665.77 ns
1,048,576336,895 ns799,979 ns167,006 ns166,945 ns

For this run, static NEON had the lowest median at 16 and 4,096 bytes. Runtime dispatch and static NEON had nearly equal medians at 1,048,576 bytes.

Check build equivalence before interpretation

An earlier large-buffer result showed the ordinary Ada loop with a lower time than the SIMD loop. That result was a build error, not an Ada language effect. The imported library algorithm lacked optimization while the benchmark unit used release optimization.

Verbose compiler commands exposed the mismatch. The project now applies -O2 to all library units. Code-generation checks also inspect the complete algorithm loop.

Do not generalize the recorded table to another host. Repeat the measurement, keep the diagnostics, and inspect the generated code. See the flyology_bench method guide for the statistical procedure.
