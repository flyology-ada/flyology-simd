Backend selection

Primitive operations use the backend selected at build time. A complete byte-buffer operation can select an optional backend once at runtime.

On this page
  • Terms
  • Static call
  • Runtime call
  • Require a backend
  • x86 safety

Use three feature terms

  • Compiled means that the selected build contains the backend code.
  • Available means that the current processor and operating system can execute that compiled code.
  • Best available is the highest-priority available backend for the current build.

Features.Compiled, Features.Available, and Features.Best_Available report these states.

Call the build-time native algorithm

Result :=
  Flyology_SIMD.Algorithms.Native.Find_First (Data, Needle);

This call uses the Backends.Native body selected by the GPR project. On a native build, Alire detects AArch64 or x86-64. A scalar scenario selects the scalar body.

The byte algorithm is a generic instantiation. GNAT can inline its primitive loads and comparisons into the loop.

Choose once for the complete buffer

Matches :=
  Flyology_SIMD.Algorithms.Runtime.Count
    (Data    => Data,
     Needle  => Flyology_SIMD.U8 (16#2C#),
     Backend => Flyology_SIMD.Features.Best_Available);

Count performs one case selection. The selected implementation then scans the complete array. No feature test runs for each vector operation.

The runtime package currently provides Find_First, Count, and Is_ASCII.

Reject an unavailable request

Call Features.Require before a forced backend call. It raises Backend_Unavailable if the backend was not compiled or cannot execute safely.

Flyology_SIMD.Features.Require (Flyology_SIMD.Features.AVX2);

Matches := Flyology_SIMD.Algorithms.Runtime.Count
  (Data, Needle, Backend => Flyology_SIMD.Features.AVX2);

The exception occurs before the program enters optional instructions.

Keep the x86-64 baseline separate from AVX2

The x86-64 baseline uses SSE2 and compiles with AVX disabled. The AVX2 algorithm code is in separate objects.

The AVX2 availability test checks AVX, OSXSAVE, XMM and YMM state in XCR0, and the AVX2 CPUID bit. A test that checks only the AVX2 bit is not sufficient.

AArch64 does not need this type of NEON gate because Advanced SIMD is part of the AArch64 baseline.
