Choose a backend

Chapter 4 composes the byte-count algorithm with the scalar reference or native backend, then selects a complete algorithm once at runtime.

On this page

  • x86 safety

The maintained count program now has equivalent source and explicit-vector results. This chapter shows where Algorithms.Scalar, Algorithms.Native, and Algorithms.Runtime make different choices.

Use three feature terms

  • Compiled means that the selected build contains the backend code.
  • Available means that the current processor and operating system can execute that compiled code.
  • Best available is NEON in an AArch64 build. In an x86-64 build, Best_Available returns AVX2 when AVX2 is compiled and available. Otherwise, it returns SSE2. It returns scalar in a scalar build.

Features.Compiled, Features.Available, and Features.Best_Available report these states.

Compose the algorithm with a backend at compile time

Algorithms.Generic_Bytes expresses the whole-buffer byte loop once. Its formal operations include splat, load, equality comparison, and mask extraction.

The library instantiates that generic package twice:

  • Algorithms.Scalar binds the operations to the portable scalar reference backend.
  • Algorithms.Native binds them to the primitive backend selected by the build.
Scalar : constant Natural :=
  Flyology_SIMD.Algorithms.Scalar.Count (Data, Comma);
Static : constant Natural :=
  Flyology_SIMD.Algorithms.Native.Count (Data, Comma);

The calls contain no per-vector runtime dispatch. GNAT can inline the selected primitive operations into the generic algorithm loop.

Alire selects AArch64 or x86-64 for a native host build. The setting FLYOLOGY_SIMD_ARCH=scalar selects the scalar native body for a forced scalar build.

Choose once per whole-buffer operation

Runtime : constant Natural :=
  Flyology_SIMD.Algorithms.Runtime.Count (Data, Comma);

Algorithms.Runtime.Count uses Features.Best_Available as its default backend. It performs one case selection. The selected implementation then scans the complete array.

No feature test or indirect call runs for each vector operation. Runtime dispatch occurs once at the whole-buffer boundary.

The runtime package currently provides Find_First, Count, and Is_ASCII.

Reject an unavailable request

Features.Backend_Kind identifies a selectable whole-buffer implementation. A forced runtime call raises Backend_Unavailable if the backend was not compiled or cannot execute safely.

Matches := Flyology_SIMD.Algorithms.Runtime.Count
  (Data, Needle, Backend => Flyology_SIMD.Features.AVX2);

Features.Require provides an optional preflight check when an application wants to reject the request before it calls an algorithm.

The runtime package raises the exception before it calls code that contains optional instructions.

Keep the x86-64 baseline separate from AVX2

The x86-64 baseline uses SSE2 and compiles with AVX disabled. The AVX2 algorithm code is in separate objects.

The AVX2 availability test checks the AVX and AVX2 processor bits. It also checks OSXSAVE, which reports operating-system support for extended processor state. The XCR0 register must enable the operating system to save the XMM and YMM register state. A test that checks only the AVX2 bit is not sufficient.

AArch64 does not need this type of NEON gate because Advanced SIMD is part of the AArch64 baseline.
