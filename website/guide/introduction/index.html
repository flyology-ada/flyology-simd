SIMD from first principles

SIMD applies one operation to several independent values. This chapter maps that model to Ada types, masks, and memory operations.

One operation changes several lanes

SIMD means single instruction, multiple data. A vector contains several lanes of one scalar type. An arithmetic or comparison operation processes corresponding lanes independently.

LaneLeftRightLeft + Right
010111
120222
230333
340444

The rows do not affect each other. A vector operation is therefore useful when an algorithm repeats the same work on adjacent values.

The width and lane type determine the lane count

This release provides 128-bit vectors. The name U8x16 means 16 unsigned 8-bit lanes. I32x4 means four signed 32-bit lanes. F64x2 means two IEEE binary64 lanes.

128 bits / 8 bits  = 16 lanes
128 bits / 32 bits =  4 lanes
128 bits / 64 bits =  2 lanes

Lane 0 is the first logical element that a load reads. Vector representation and calling conventions are private. Do not pass a vector through a foreign-language call boundary by assuming a register layout.

A comparison returns one Boolean per lane

A vector comparison does not return one Boolean. It returns a private mask type. For example, an equality comparison on U8x16 returns Mask_8x16.

values:  41  42  41  43
needle:  41  41  41  41
equal:    T   F   T   F
bits:     1   0   1   0  = compact mask 0b0101

Use Any_True to ask whether at least one lane is true. Use All_True to require every lane. Use To_Bit_Mask when an algorithm needs a compact integer. Bit 0 represents lane 0.

Use Mask_And, Mask_Or, Mask_Xor, and Mask_Not to combine conditions. Do not depend on the private mask representation.

Choose wrapping or saturating integer arithmetic

Public semantics do not depend on the instruction that implements an operation. The API uses different names for different overflow rules.

OperationExample for an unsigned 8-bit lane
Add_Wrap250 + 10 becomes 4 modulo 256
Add_Saturate250 + 10 becomes 255

Shift counts at least as large as the lane width also have fixed results. Logical shifts return zero. An arithmetic right shift returns the sign fill.

Load complete vectors and process the final partial vector

A complete load requires one full vector of valid elements. Load_Unaligned does not require 16-byte alignment. Load_Aligned requires a 16-byte-aligned address.

A buffer length is rarely an exact multiple of the lane count. Use Load_Partial for the final elements. It reads exactly Count elements and fills the remaining lanes with zero. Store_Partial writes exactly Count elements.

A partial load is not a masked out-of-range load.

The implementation does not read a complete vector and discard invalid lanes. Protected-page tests check every byte count from 0 through 16.

Keep semantics separate from the machine backend

Flyology_SIMD is the scalar reference. It defines the portable result. Flyology_SIMD.Backends.Native provides the backend selected at build time.

Use the compile-time-selected native package for direct vector operations and reusable compiled algorithms. Use Algorithms.Runtime when one whole-buffer operation must select from the backends that the processor and operating system can execute.

Runtime dispatch occurs once for the buffer. It does not occur for each vector operation or lane.

Put the operations into a complete loop

This outline adds 10 with saturation. It uses the compiled native backend and handles the final partial vector.

package Native renames Flyology_SIMD.Backends.Native;

Start := Data'First;
while Start <= Data'Last loop
   Count := Lane_Count_8x16'Min (16, Data'Last - Start + 1);
   Value := Native.Load_Partial (Data, Start, Count);
   Value := Native.Add_Saturate (Value, Native.Splat (10));
   Native.Store_Partial (Data, Start, Count, Value);
   Start := Start + Count;
end loop;
