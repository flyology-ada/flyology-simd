Run the complete byte-count program

The program counts comma bytes in "red,green,blue,amber,white". Clone the repository and run the maintained source:

git clone https://github.com/flyology-ada/flyology-simd.git
cd flyology-simd
alr exec -- gprbuild -p -P examples/examples.gpr
./bin/count_byte

The five count lines include an explicit U8x16 loop. They have the following output:

ordinary source loop: 4
explicit U8x16 loop: 4
scalar reference backend: 4
static native algorithm: 4
runtime-dispatched algorithm: 4

The final line reports neon, sse2, avx2, or scalar. The value depends on the build and host:

best available backend: neon

Use scalar for one value at a time

A scalar operation acts on one value. The ordinary Ada source loop compares one U8 element in each source iteration.

The scalar reference backend implements each vector result with portable lane-by-lane Ada. It is the semantic authority for optimized backends. It is not the same concept as the ordinary source loop.

Generated machine code is the compiler output. GNAT can auto-vectorize an ordinary Ada source loop. Therefore, scalar source does not prove that the executable contains only scalar instructions.

This guide uses explicit vector loop for source that calls fixed-width vector operations. The backend can implement an explicit operation with one instruction, several instructions, or scalar composition.

Compare five implementations of the same count

The input is a Byte_Array. Each implementation counts the same comma value and returns Natural.

  • Ordinary_Count is the direct Ada source loop.
  • Explicit_Count_Commas calls Backends.Native operations directly.
  • Algorithms.Scalar.Count runs the reusable algorithm instantiated with the scalar reference backend.
  • Algorithms.Native.Count runs the instance bound to the backend selected at build time.
  • Algorithms.Runtime.Count selects one safe implementation before it scans the complete buffer.

Equal results establish the required semantics. They do not establish equal generated code or equal performance.

Measure before adding explicit SIMD

An explicit U8x16 iteration compares 16 byte candidates. The ordinary source loop compares one candidate per source iteration. GNAT can still auto-vectorize the ordinary loop.

A recorded 2026-08-10 run measured 4,096-byte counts on an Apple Mac15,9 AArch64 host with GNAT FSF 16.1.0. The ordinary Ada count had a 1,349.29 ns median. The static NEON count had a 661.40 ns median.

The run used 75 repeated samples. It did not use CPU pinning or a quiescence check. This result motivates inspection on that host; it is not a portable ratio. Chapter 5 gives the switches, method, other sizes, and reproduction commands.

Add the crate to an application

Add the Flyology index once. You can run these index commands from any directory:

alr index --reset-community
alr index --add=git+https://github.com/flyology-ada/alire-index.git \
  --name=flyology --before=community

Keep the community index. Alire uses it to find the compiler toolchain. Run alr index --list to inspect the configured indexes.

Then change to the root of your own Alire application. Add the crate there, not in the flyology-simd checkout:

cd /path/to/your/application
alr with flyology_simd
alr build

The GPR project detects aarch64 and x86_64 hosts. You do not need to set FLYOLOGY_SIMD_ARCH for a native build. Use an override for a scalar-only test or for cross-compilation.

alr build -- -XFLYOLOGY_SIMD_ARCH=scalar
Standalone crate

The library has no runtime dependency on Flyology. It defines Flyology_SIMD, not a Flyology parent package.

Follow the guide in order

The chapters build one model. Each chapter assumes the result of the previous chapter.

  1. Process one 16-byte block

    Load bytes into lanes, compare them with one comma value, and count the true mask lanes.

  2. Build the complete explicit loop

    Repeat the block operation across the input and keep the result equivalent to the ordinary loop.

  3. Handle the final partial block

    Read the remaining bytes without reading beyond the caller-declared extent.

  4. Compose and select backends

    Separate scalar reference composition, static native composition, and coarse runtime dispatch.

  5. Measure and inspect the algorithm

    Compare complete counts, inspect generated code, and keep conclusions within the measured environment.

Know what this guide does not promise

The operation matrix is a reference, not a chapter in the byte-count walkthrough. Use it to check type coverage and exact edge semantics.

The API is experimental. The current value family is 128 bits wide. The operation matrix lists missing shuffle, table-lookup, and 256-bit work.

The scalar backend defines the result on every supported GNAT target. Target-specific code exists for AArch64 NEON and x86-64 SSE2, with an AVX2 path for selected whole-buffer byte algorithms. The support page distinguishes implemented, executed, and continuously tested configurations.
