Run one complete program

The first program answers one question: where is the first exclamation-mark byte in an Ada array? Clone the repository and run the maintained source:

git clone https://github.com/flyology-ada/flyology-simd.git
cd flyology-simd
alr exec -- gprbuild -p -P examples/examples.gpr
./bin/find_byte

Expected output:

Found '!' at Ada array index 21

The build creates all maintained examples in bin. This first run uses a whole-buffer operation, so backend selection and tail handling remain inside the library.

Read what the program did

The input is a Byte_Array with bounds 1 through 23. Its U8 elements hold byte values. The value 33 is element 21 and represents '!'.

Data : Byte_Array (1 .. 23) :=
  [70, 108, 121, 111, 108, 111, 103, 121, 32, 83, 73, 77, 68,
   32, 105, 115, 32, 65, 100, 97, 33, 10, 0];

Result : constant Algorithms.Search_Result :=
  Algorithms.Runtime.Find_First
    (Data, U8 (Character'Pos ('!')));

Algorithms.Runtime.Find_First selects one safe backend before it scans the array. The function returns an Algorithms.Search_Result that contains Ada index 21, not a zero-based byte offset.

This call hides its vector loop. Chapter 2 builds a different vector loop and shows how loads, comparisons, masks, reductions, and a partial tail compose.

Add the crate to an application

Add the Flyology index once. You can run these index commands from any directory:

alr index --reset-community
alr index --add=git+https://github.com/flyology-ada/alire-index.git \
  --name=flyology --before=community

Keep the community index. Alire uses it to find the compiler toolchain. Run alr index --list to inspect the configured indexes.

Then change to the root of your own Alire application. Add the crate there, not in the flyology-simd checkout:

cd /path/to/your/application
alr with flyology_simd
alr build

The GPR project detects aarch64 and x86_64 hosts. You do not need to set FLYOLOGY_SIMD_ARCH for a native build. Use an override for a scalar-only test or for cross-compilation.

alr build -- -XFLYOLOGY_SIMD_ARCH=scalar
Standalone crate

The library has no runtime dependency on Flyology. It defines Flyology_SIMD, not a Flyology parent package.

Follow the guide in order

The chapters build one model. Each chapter assumes the result of the previous chapter.

  1. SIMD from first principles

    Learn vector width, lanes, masks, overflow names, and the difference between semantics and representation.

  2. Build complete SIMD tasks

    Start with a whole-buffer call. Then build a byte classifier and a floating-point transform from direct operations.

  3. Handle memory and tails

    Connect lane order to Ada array indexes. Process every length without an out-of-bounds full-vector read.

  4. Choose a backend

    Separate compile-time primitive selection from one runtime choice at a whole-buffer boundary.

  5. Check operation semantics

    Use the family matrix and exact edge contracts for arithmetic, masks, conversion, reduction, and memory.

  6. Measure a complete algorithm

    Build the standalone benchmark, keep candidate work equivalent, and interpret repeated measurements.

Know what this guide does not promise

The API is experimental. The current value family is 128 bits wide. The operation matrix lists missing conversion, shuffle, table-lookup, and 256-bit work.

The scalar backend defines the result on every supported GNAT target. Target-specific code exists for AArch64 NEON and x86-64 SSE2, with an AVX2 path for selected whole-buffer byte algorithms. The support page distinguishes implemented, executed, and continuously tested configurations.
