New to SIMD?

Read SIMD from first principles first. It explains lanes, masks, vector width, overflow rules, partial memory operations, and backend selection. Each concept links to this library's Ada API.

Install from the Flyology Alire index

flyology_simd version 0.1.0-dev is in the Flyology index. Keep the community index because Alire uses it to find the compiler toolchain.

alr index --reset-community
alr index --add=git+https://github.com/flyology-ada/alire-index.git \
  --name=flyology --before=community
alr with flyology_simd
alr build

You only add the Flyology index once. Run alr index --list to see the configured indexes.

The GPR project detects aarch64 and x86_64 hosts. You do not need to set FLYOLOGY_SIMD_ARCH for a native build. Use an override for a scalar-only test or for cross-compilation.

alr build -- -XFLYOLOGY_SIMD_ARCH=scalar
Standalone crate

The library has no runtime dependency on Flyology. It defines Flyology_SIMD, not a Flyology parent package.

Build the repository examples

Run this command from the repository root:

alr exec -- gprbuild -p -P examples/examples.gpr

The command creates five programs in bin. Run them from the repository root:

./bin/find_byte
./bin/integer_vectors
./bin/floating_vectors
./bin/partial_tail
./bin/backend_selection

The continuous build compiles these examples. This check prevents the guide from depending on stale source.

Search a complete byte array

Algorithms.Runtime.Find_First selects one available backend before it scans the array. The processor and operating system can execute an available backend. The function returns an Ada array index, not a zero-based byte offset.

with Ada.Text_IO;
with Flyology_SIMD;
with Flyology_SIMD.Algorithms.Runtime;

procedure Find_Byte is
   Data : Flyology_SIMD.Byte_Array (1 .. 6) :=
     [83, 73, 77, 68, 33, 10];
   Result : constant Flyology_SIMD.Algorithms.Search_Result :=
     Flyology_SIMD.Algorithms.Runtime.Find_First
       (Data, Flyology_SIMD.U8 (Character'Pos ('!')));
begin
   if Result.Found then
      Ada.Text_IO.Put_Line ("Found at" & Result.Index'Image);
   end if;
end Find_Byte;

The value 33 is '!'. It is the fifth element of this array. The program prints Found at 5.

Choose the integer overflow rule

The direct-vector examples use Flyology_SIMD.Backends.Native. This package is the compiled target backend. The scalar root package defines the reference semantics.

This example uses U16x8 to add 10 to eight unsigned 16-bit lanes. It calls the native Add_Wrap and Add_Saturate overloads:

package Native renames Flyology_SIMD.Backends.Native;

Input : constant U16x8 :=
  Native.From_Lanes ([65_530, 1, 2, 3, 100, 200, 300, 400]);
Increment : constant U16x8 := Native.Splat (10);

Wrapped : constant U16x8 := Native.Add_Wrap (Input, Increment);
Saturated : constant U16x8 := Native.Add_Saturate (Input, Increment);

Extract (Wrapped, 0) returns 4 because wrapping addition is modulo 65,536. Extract (Saturated, 0) returns 65,535 because saturating addition clamps to the lane maximum.

The complete integer_vectors example also compares every lane with 150. The result is a Mask_16x8. Bit 0 of its compact mask represents lane 0.

Use the floating-point family

F32x4 contains four IEEE binary32 lanes. The following code multiplies each lane by 2 and compares each result with zero:

Samples : constant F32x4 :=
  Native.From_Lanes ([-1.5, 0.0, 2.25, 10.0]);
Scaled : constant F32x4 :=
  Native.Multiply (Samples, Native.Splat (2.0));
Negative : constant Mask_32x4 :=
  Native.Less_Than (Scaled, Native.Zero);

The scaled lanes are -3.0, 0.0, 4.5, and 20.0. Only lane 0 is negative, so To_Bit_Mask (Negative) returns 1.

The default build does not enable fast-math. Read the floating operation table before code depends on NaN or signed-zero behavior.

Choose one of three interfaces

NeedInterfaceBackend decision
Direct vector operationsFlyology_SIMD for scalar semantics or Backends.Native for the compiled targetAt build time
A reusable generic byte loopAlgorithms.Generic_BytesAt generic instantiation
A complete byte-buffer operationAlgorithms.RuntimeOnce per operation

The runtime interface does not detect features for each vector addition or comparison. It selects an implementation once, then that implementation runs the vector loop.
