The earlier loops used partial loads, comparisons, masks, arithmetic, minimum, maximum, and reductions. This chapter shows whether another primitive exists and defines its result on every backend.

Public vector and mask types

Each value vector is 128 bits. The type name gives the scalar type and lane count. For example, I32x4 contains four signed 32-bit lanes.

Lane typeValue typesMask type
8-bit integerU8x16, I8x16Mask_8x16
16-bit integerU16x8, I16x8Mask_16x8
32-bit integer or floatU32x4, I32x4, F32x4Mask_32x4
64-bit integer or floatU64x2, I64x2, F64x2Mask_64x2

Lane 0 is the first array element that a load reads. A compact mask uses bit 0 for lane 0. Bits above the mask lane count are ignored when you construct a mask.

Convert bits and lane widths explicitly

Bit_Cast preserves each lane's bits and position. Source and result types must have the same lane width and count.

For example, the F32x4-to-U32x4 overload returns four IEEE binary32 encodings. It does not perform numeric conversion.

Integer widening preserves each numeric lane value. It zero-extends unsigned lanes and sign-extends signed lanes. Floating widening converts each finite F32 value exactly to F64. It preserves signed zero and infinity. A NaN input produces a NaN result, but payload and signaling state are unspecified.

Each narrowing operation takes two source vectors. Low supplies the low result half, and High supplies the high result half.

The Byte_Array type supplies typed input. The Load_Unaligned overload reads its bytes in lane order. This complete declaration uses the array's actual first index:

Input : constant Byte_Array :=
  [0, 17, 34, 51, 68, 85, 102, 119,
   136, 153, 170, 187, 204, 221, 238, 255];

Low_Bytes  : constant U8x16 :=
  Load_Unaligned (Input, Input'First);
Low_Words  : constant U16x8 := Widen_Low (Low_Bytes);
High_Words : constant U16x8 := Widen_High (Low_Bytes);
Round_Trip : constant U8x16 :=
  Narrow_Saturate (Low_Words, High_Words);

The round trip returns the original bytes because unsigned widening is lossless. Signed-to-unsigned saturation maps negative inputs to zero.

The From_Lanes overload constructs the next wide values. Zero supplies the high source half. The results show why the narrowing names are different:

Wide : constant U16x8 :=
  From_Lanes ([254, 255, 256, 300, 0, 1, 2, 3]);
Empty : constant U16x8 := Zero;

Truncated : constant U8x16 :=
  Narrow_Truncate (Wide, Empty);
Saturated : constant U8x16 :=
  Narrow_Saturate (Wide, Empty);

--  Truncated lanes 0 .. 3: 254, 255, 0, 44
--  Saturated lanes 0 .. 3: 254, 255, 255, 255

Floating narrowing gives the results below when the floating-point environment uses its default round-to-nearest, ties-to-even mode. The library does not modify the floating-point control register. The operation preserves signed zero and infinity. A finite value that overflows binary32 after rounding produces infinity with the same sign. Gradual underflow can produce a binary32 subnormal. A sufficiently small magnitude rounds to signed zero. A NaN remains a NaN, but its payload and signaling state are unspecified.

Low : constant F64x2 :=
  From_Lanes
    ([1.000_000_059_604_644_775_390_625,
      1.000_000_178_813_934_326_171_875]);
High : constant F64x2 := From_Lanes ([-0.0, 4.0]);
Rounded : constant F32x4 := Narrow_Round (Low, High);

--  Rounded lane bits: 16#3F80_0000#, 16#3F80_0002#,
--                     16#8000_0000#, 16#4080_0000#

Low lane 0 becomes result lane 0. Low lane 1 becomes result lane 1. Both source values are exact midpoints. Lane 0 rounds down to 16#3F80_0000#, and lane 1 rounds up to 16#3F80_0002#. Both results have an even low bit. High lanes 0 and 1 become result lanes 2 and 3. Therefore, negative zero appears in result lane 2.

The maintained conversions.adb example prints the four encodings as decimal integers:

F64 narrowed bits: 1065353216 1065353218 2147483648 1082130432

Convert_Round keeps the lane count and lane positions. Source lane n becomes result lane n. The operation requires the platform's default round-to-nearest, ties-to-even environment. It does not modify the floating-point control register. Integer magnitudes through 224 are exact in F32. Integer magnitudes through 253 are exact in F64.

Integers : constant I32x4 :=
  From_Lanes ([0, 16_777_216, 16_777_217, I32'Last]);
Floats : constant F32x4 := Convert_Round (Integers);
Bits : constant U32x4 := Bit_Cast (Floats);

--  Bits: 16#0000_0000#, 16#4B80_0000#,
--        16#4B80_0000#, 16#4F00_0000#

Lane 0 remains zero. Lane 1 is exact. Lane 2 contains 16,777,217, which is halfway between two binary32 values. It rounds to 16,777,216 because ties-to-even selects the result with an even low bit. Lane 3 contains the largest I32 value. It rounds to 231. All integer-to-floating results are finite.

The maintained example prints these encodings as decimal integers:

I32 rounded bits: 0 1266679808 1266679808 1325400064

Convert_Truncate_Saturate keeps the lane count and lane positions. It truncates a finite value toward zero, then clamps it to the result range. A negative value becomes zero in an unsigned result. Positive infinity becomes the destination maximum. Negative infinity becomes the destination minimum for a signed result and zero for an unsigned result. A NaN becomes zero. The operation does not depend on or modify the floating-point rounding mode.

Input_Bits : constant U32x4 :=
  From_Lanes
    ([16#BFE0_0000#, 16#3FE0_0000#, 16#4F00_0000#, 16#7FC0_0001#]);
Inputs : constant F32x4 := Bit_Cast (Input_Bits);

Signed : constant I32x4 := Convert_Truncate_Saturate (Inputs);
Unsigned : constant U32x4 := Convert_Truncate_Saturate (Inputs);

--  Inputs:   -1.75, 1.75, 2**31, NaN
--  Signed:   -1, 1, I32'Last, 0
--  Unsigned:  0, 1, 2**31, 0

Lane 0 shows truncation and unsigned clamping. Lane 1 shows truncation for a positive value. Lane 2 exceeds the signed range but remains in the unsigned range. Lane 3 shows the defined NaN result.

The maintained example prints:

F32 to I32:-1 1 2147483647 0
F32 to U32: 0 1 2147483648 0

Convert_Saturate changes signedness without changing the lane width, lane count, or lane positions. A negative signed input becomes zero. An unsigned input above the signed maximum becomes the signed maximum. All other values are preserved.

Signed_Input : constant I32x4 :=
  From_Lanes ([-1, 0, 1, I32'Last]);
Unsigned_Result : constant U32x4 := Convert_Saturate (Signed_Input);

Unsigned_Input : constant U32x4 :=
  From_Lanes ([0, 2_147_483_647, 2_147_483_648, U32'Last]);
Signed_Result : constant I32x4 := Convert_Saturate (Unsigned_Input);

--  Unsigned_Result: 0, 0, 1, 2_147_483_647
--  Signed_Result:   0, 2_147_483_647, 2_147_483_647, 2_147_483_647

The maintained example prints:

I32 to U32: 0 0 1 2147483647
U32 to I32: 0 2147483647 2147483647 2147483647

Horizontal_Sum remains as a byte-specific convenience. It returns the exact sum as Natural. For U8x16, Reduce_Add_Wrap returns the sum modulo 256.

A logical shift returns zero in each lane when its count is equal to or greater than the lane width. An arithmetic right shift returns the sign fill for those counts.

The build does not enable -ffast-math. Ordered comparisons are false when either lane is NaN. Unordered is true for that case.

Min_Number and Max_Number return the numeric input when only one quiet NaN is present. They select negative zero for a minimum and positive zero for a maximum. The API reference and semantic document give the full NaN rules.

Reduce_Min_Number and Reduce_Max_Number use lane 0 as the initial result. They combine each remaining lane with that result in ascending order. Each step applies the documented NaN and signed-zero rules on every backend.

Samples : constant F32x4 := From_Lanes ([4.5, -2.0, 7.25, 1.0]);
Smallest : constant F32 := Reduce_Min_Number (Samples);  --  -2.0
Largest  : constant F32 := Reduce_Max_Number (Samples);  --   7.25

The ordinary values above make the result easy to check. See the semantic compatibility document for NaN and signed-zero results.

Combine and inspect masks

A mask is a Boolean value for each lane. It is not an integer vector. Use these operations instead of depending on its private representation:

  • Mask_And, Mask_Or, Mask_Xor, and Mask_Not combine lane truths.
  • Test reads one lane truth.
  • Any_True, All_True, and None_True reduce the mask to one Boolean.
  • Population_Count counts true lanes.
  • First_True and Last_True return the lowest or highest true lane.
  • Mask_From_Bit_Mask constructs a mask from the low lane-count bits of a compact integer.
  • To_Bit_Mask returns a compact mask. Bit n represents lane n.

A mask-position result is a valid lane index when it is less than Lane_Count_8x16'Last. The last value, 16 for this mask, means that no lane is true. The same rule applies to the other mask widths.

Input : constant Byte_Array (1 .. 16) :=
  [97, 98, 99, 44, 100, 101, 102, 44,
   103, 104, 105, 106, 107, 108, 109, 110];
Bytes : constant U8x16 := Load_Unaligned (Input, Input'First);
Commas : constant Mask_8x16 := Equal (Bytes, Splat (44));
First_Comma : constant Lane_Count_8x16 := First_True (Commas);
Last_Comma  : constant Lane_Count_8x16 := Last_True (Commas);

if First_Comma /= Lane_Count_8x16'Last then
   --  First_Comma is 3 and Last_Comma is 7.
   --  Both values can now be converted to Lane_Index_8x16.
end if;

The Byte_Array input is abc,def,ghijklmn. Load_Unaligned reads its 16 bytes. Lane indexes start at zero, so the comma positions are 3 and 7. The sentinel check comes before any conversion to Lane_Index_8x16.

Use typed arrays for memory operations

Each family has Load, Store, aligned variants, unaligned variants, and safe partial variants. Full operations require one complete vector of valid elements.

Has_Extent is a byte-family helper. It reports whether Count byte elements fit from Start. Is_Aligned_16 reports whether that byte element address is 16-byte aligned.

A partial load reads exactly Count elements and fills the remaining lanes with zero. A partial store writes exactly Count elements. A count of zero touches no element.

Reverse_Bytes is the byte-specific compatibility name for Reverse_Lanes. Horizontal_Sum is the byte-specific exact-sum convenience operation.

See the memory guide for a complete tail loop.

Not implemented in 0.1.0-dev

The following groups are design targets, not current API:

  • arbitrary lane-index shuffles, byte-table lookup, lane slides, and compression;
  • 256-bit vector and mask types;
Coverage statement

“Full family” means that all ten 128-bit value types exist. It does not mean that every operation planned for the project exists.
