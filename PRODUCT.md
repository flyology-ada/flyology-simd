# Product

## Register

brand

## Users

Ada library and application developers use this site while selecting vector
types, checking exact operation semantics, composing buffer algorithms, and
validating target support. They need a short path from a conceptual guide to
the declaration that defines a contract.

## Product Purpose

The site explains how `flyology_simd` provides explicit portable SIMD without
exposing target representation. It must help a reader install the crate, choose
static or runtime composition, use memory operations safely, and distinguish
implemented support from planned work. Success means the guide, architecture,
and generated API agree with the source and make limitations easy to find.

## Brand Personality

Precise, mechanical, and evidence-led. The voice is direct and technically
confident without promotional performance claims.

## Anti-references

Do not imitate a generic developer-tool landing page, a neon terminal theme, a
dashboard of vanity metrics, or an instruction-set catalog. Do not present
unverified targets, local benchmark observations, or deferred API work as
general capability.

## Design Principles

1. Show portable semantics before target mechanisms.
2. Make safety conditions visible beside each memory operation.
3. Connect every public identifier in prose to its generated API entry.
4. Use diagrams and lane examples to explain data movement.
5. Separate measured evidence from general claims.

## Accessibility & Inclusion

Meet WCAG 2.2 AA for authored pages. Support keyboard navigation, visible
focus, reduced motion, semantic headings, useful link text, and light and dark
color schemes. Do not rely on color alone to distinguish lanes, masks, or
backend status.
